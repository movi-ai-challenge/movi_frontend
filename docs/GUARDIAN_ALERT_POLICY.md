# 보호자 알림 전용 정책

> 확정일: 2026-08-24 · 백엔드 계약 확인: 2026-08-25

보호자는 사용자의 금융 업무를 대신 처리하거나 금융 정보를 조회하는 역할이 아니다. 보호자는 FDS가 위험 거래를 감지했을 때 알림을 받는 연락 대상이다.

## 허용 범위

- 사용자가 보호자 연락처를 등록하고 연결한다.
- 백엔드가 위험 거래를 판정하면 연결된 보호자 알림을 비동기로 처리한다.
- 보호자는 알림에서 위험 거래의 존재와 필요한 최소 정보를 확인한다.
- 공개 조회 API가 제공되는 경우에만 알림 발송 상태를 프런트에서 안내한다.

## 금지 범위

- 보호자의 계좌·잔액·거래내역 조회
- 보호자의 이체 승인 또는 거절
- 보호자의 이체 시작·실행·취소
- 보호자의 계좌 설정 변경
- 조회·이체 승인 권한 설정 화면
- 보호자용 금융 대시보드와 거래 통계

보호자 연결 과정에서 연락 수신에 동의하는 절차는 금융 거래 승인 권한과 다른 개념이다. 연결 동의가 필요하더라도 금융 정보 접근 권한은 부여하지 않는다.

## 현재 코드에 미치는 영향

- `feature/7-5-guardian-permissions`의 미커밋 구현은 폐기했다.
- `feature/7-3-guardian-connection-approval`은 원격에 존재하지만 새 정책에 맞는 연결 수신 동의인지 재검토하기 전에는 병합하지 않는다.
- `main`의 5.7 중위험 보호자 승인 대기 화면은 새 정책과 충돌한다. MEDIUM 거래 완료 화면으로 교체한다.
- 7.4 가족 관계 정보가 알림 연락처에 필요한지는 `확인 필요`다. 불필요하다고 결정되면 해당 기능도 범위에서 제외한다.
- 보호자 대시보드 9.x와 보호자 권한 설정 7.5는 현재 범위 밖이다.

## 확정된 위험도별 처리

- LOW + ALLOW: 이체 완료, 보호자 알림 없음
- MEDIUM + ALLOW_WITH_ALERT: 이체 완료 후 보호자 알림
- HIGH + BLOCK: 이체 차단 후 보호자 긴급 알림
- FDS 타임아웃·통신 오류·잘못된 응답: 이체 미실행

보호자 알림 발송과 최대 3회 재시도는 백엔드가 담당한다. 프런트는 이를 시작하거나 승인 결과를 기다리지 않는다.

## 확인 필요

- 알림 채널: SMS, 앱 푸시 또는 복수 채널
- 보호자에게 표시할 최소 정보와 마스킹 기준
- 알림 링크의 본인 확인 및 만료 방식
- 보호자 초대·수락·조회용 공개 API와 시연 Seed 준비 방식
- 알림 발송 상태 공개 조회 API 제공 여부

위 항목이 확정되기 전에는 보호자 연결·알림 조회 API를 프런트엔드에서 임의로 만들지 않는다. 보호자의 거래 승인이나 금융 정보 조회 동작은 구현하지 않는다.
