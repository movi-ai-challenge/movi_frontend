# MOVI 인증·권한·금융 안전 체크리스트

> 최신 정책 반영: 2026-08-27
> 최신 확정 결정: [DECISIONS_2026-08-27.md](DECISIONS_2026-08-27.md)
> 상위 기준: [IMPLEMENTATION_SOURCE_OF_TRUTH.md](IMPLEMENTATION_SOURCE_OF_TRUTH.md)
> API 계약: [backend-frontend-integration-decisions.md](backend-frontend-integration-decisions.md)

## 변경할 수 없는 원칙

- 음성 인식 결과만으로 로그인이나 송금을 완료하지 않는다.
- 금융 거래는 수취인, 금액, 출금 계좌를 검토하고 명시적으로 확인한다.
- 보호자는 위험 거래 알림만 받으며 금융 조회·승인·거절 권한이 없다.
- 프런트 버튼 비활성화나 URL 숨김을 보안 통제로 간주하지 않는다.
- 인증, 소유권, 한도, FDS와 최종 금융 상태는 백엔드가 검증한다.
- 계좌번호, 전화번호, 토큰과 원문 transcript를 URL·로그·Git·오류에 노출하지 않는다.

## MVP 보호 수준

| 기능 | 보호 방식 | 사용자 확인 |
| --- | --- | --- |
| 계좌·잔액·거래 조회 | Access token + 백엔드 소유권 검증 | 조회는 별도 최종 확인 불필요 |
| 기본 계좌·별칭 변경 | Access token + 백엔드 소유권·규칙 검증 | 변경 버튼 |
| 최초 OpenBanking 연결 | Access token + OpenBanking 본인 인증 + 5분·1회용 state | 연결 시작 |
| PIN 최초 등록 | 카카오 로그인 직후 인증 사용자 | 6자리 PIN 입력 확인 |
| 송금 | Access token + `confirmationId` + 1회용 확인 코드 + 필요 시 거래 결속 PIN proof + `idempotencyKey` + FDS | 수취인·금액·출금 계좌 검토 후 실행 |
| 위험 거래 알림 | 검증된 FDS 결과에 따른 백엔드 이벤트 | 사용자 화면에서 발송하지 않음 |

계좌 추가 연결·연결 해제, PIN 변경·재설정·분실 복구, 생체인증·Passkey와 보호자 연결 공개 흐름은 MVP에서 제외한다. 기존 PIN을 이용한 거래 결속 proof는 송금 보호 수단으로 포함한다.

## 카카오 로그인 (과거 `#19` 구현)

- [x] callback URL의 Access/Refresh token 파싱을 제거했다.
- [x] URL에는 일회성 `code`만 사용한다.
- [x] `POST /api/v1/auth/kakao/token`으로 `{ code }`를 교환한다.
- [x] callback query를 즉시 제거한다.
- [x] 교환 응답을 `unknown`에서 런타임 검증한다.
- [x] Access token을 메모리에만 보관한다.
- [x] Refresh token을 `sessionStorage`에 분리 보관한다.
- [x] 코드 누락·만료·재사용 오류 안내가 있다.
- [ ] OAuth 성공·취소·state 오류·카카오 오류가 모두 프런트로 복귀한다.
- [x] `newUser` 사용자를 PIN 등록 화면으로 보낸다.
- [x] 기존 사용자는 실제 PIN 로그인 또는 계좌 화면으로 안전하게 이동한다.
- [ ] staging 실제 카카오 계정 E2E를 통과한다.
- [ ] 배포 후 백엔드 `legacy-token-query=false`를 확인한다.
- [ ] URL, 브라우저 기록, 프록시·Netlify 로그에 토큰이 없음을 확인한다.

## 세션과 공통 API

- [x] 공통 `ApiResponse<T>` 성공·실패 파서가 있다.
- [x] Access token을 Authorization 헤더에 주입한다.
- [x] Refresh token은 요청 본문 외 URL·로그에 넣지 않는다.
- [x] 동시에 여러 401이 발생해도 refresh는 한 번만 수행한다.
- [x] refresh 성공 후 원 요청을 한 번만 재시도한다.
- [x] refresh 실패 시 토큰과 금융 store를 지우고 로그인으로 이동한다.
- [x] 403을 권한 부족으로 안내하며 재로그인을 반복하지 않는다.
- [x] 보호 경로 직접 접근을 인증 경계에서 차단한다.
- [x] 안전한 내부 `next` 경로만 로그인 후 복귀에 사용한다.
- [x] logout API 호출 후 인증·계좌·송금·음성 상태를 정리한다.
- [x] 새로고침 후 Refresh token으로 Access token을 복구한다.
- [ ] 다중 탭의 logout·만료 동작을 검증한다.

## PIN

- [x] 신규 카카오 사용자인지 백엔드 응답으로 판단한다.
- [x] PIN은 6자리 규칙을 프런트에서 사전 검증한다.
- [x] PIN 원문을 store, 로그, URL과 오류 메시지에 남기지 않는다.
- [x] PIN 등록은 인증된 신규 사용자만 호출한다.
- [x] 기존 사용자의 전화번호+PIN 로그인을 실제 API에 연결한다.
- [x] 잘못된 PIN, 잠금, 만료와 네트워크 오류를 구분해 안내한다.
- [x] PIN 성공을 송금 최종 확인으로 재사용하지 않는다.

## OpenBanking과 조회 권한

- [ ] callback 공개 경로가 운영 인증 모드에서 401로 차단되지 않는다.
- [ ] state 누락·만료·재사용 시 계좌를 연결하지 않는다.
- [ ] callback 성공·취소·오류 후 프런트 화면으로 복귀한다.
- [x] 프런트 callback 복귀 후 인증된 계좌 API를 다시 조회한다.
- [ ] 다른 사용자의 계좌·잔액·거래 ID 접근을 백엔드가 거부한다.
- [x] 계좌번호는 화면·TTS·오류·로그에서 마스킹한다.
- [x] 계좌 추가 연결·연결 해제 UI를 실제 MVP 경로에서 제공하지 않는다.

## 송금·멱등성·FDS

- [ ] 등록 수취인 선택 기반의 비음성 송금이 서버 검토 → 명시적 확인 → 필요 시 PIN proof → 멱등 실행 순서로 완료된다.
- [ ] 수취인, 금액과 출금 계좌를 서버 응답으로 검토 화면에 표시한다.
- [x] 화면 또는 음성 검토 후 별도의 명시적 확인이 있다.
- [ ] 서버가 무작위 6자리 확인 코드를 발급하며 60초·1회용·최대 3회 시도를 강제한다.
- [ ] 수취인·금액·출금 계좌가 바뀌면 `confirmationId`, 확인 코드와 PIN proof가 모두 무효화된다.
- [ ] PIN proof가 필요한 거래는 해당 거래에 결속된 유효 proof 없이는 실행되지 않는다.
- [x] `confirmationId`를 다른 거래에 재사용하지 않는다.
- [x] `AWAITING_CONFIRMATION`부터 `idempotencyKey`를 보관한다.
- [ ] 중복 클릭·순차·동시 요청에도 이체는 한 건이다.
- [x] timeout·새로고침 후 같은 키로 최종 상태를 조회한다.
- [x] 프런트가 FDS 위험도나 결정 값을 만들지 않는다.
- [ ] FDS 원본 0~100 점수와 정책 버전을 보존하고 점수를 사기 확률로 표시하거나 임의로 100으로 나누지 않는다.
- [x] LOW는 완료, MEDIUM은 완료+알림 요청, HIGH·CRITICAL은 차단+알림 요청으로 표시한다.
- [ ] Voice/FDS timeout·5xx·잘못된 payload에서 이체가 실행되지 않는다.
- [x] HIGH·CRITICAL 차단을 PIN 등 추가 인증으로 우회하는 UI가 없다.
- [x] 성공 화면은 백엔드에서 확정한 최종 상태만 표시한다.

## 보호자 알림

- [ ] 보호자를 위험 거래 알림 수신자로만 설명한다.
- [ ] 보호자 금융 조회·승인·거절 UI가 없다.
- [ ] Seed 보호자와 백엔드 이벤트만 사용한다.
- [ ] 초대·수락·관계 입력·연결·해제 화면을 MVP에서 제공하지 않는다.
- [x] guardian `riskEventId` 공개 조회 화면·서비스를 실제 경로에서 제거한다.
- [ ] 프런트가 알림 발송이나 재시도를 시작하지 않는다.
- [x] 사용자 안내는 “보호자에게 알림을 요청했어요.”로 제한한다.
- [x] “문자 발송이 완료됐다”는 문구가 없다.
- [ ] SMS 링크와 계좌번호 포함 메시지가 없다.
- [ ] SMS 실패가 완료된 MEDIUM 이체를 실패로 바꾸지 않는다.

## 접근성과 오류 안전

- [ ] 인증·금융 주요 흐름을 키보드만으로 완료한다.
- [ ] 오류 발생 후 포커스가 오류 요약 또는 복구 행동으로 이동한다.
- [ ] loading·success·warning·error를 색상만으로 전달하지 않는다.
- [ ] 중요한 비동기 상태를 live region으로 안내한다.
- [ ] TTS 실패가 금융 결과를 바꾸지 않는다.
- [ ] 마이크 거부·미지원·네트워크 오류에 직접 입력 대안이 있다.
- [ ] 200% 확대와 모바일 reflow를 통과한다.
- [ ] VoiceOver/TalkBack에서 수취인·금액·계좌·결과를 이해할 수 있다.
