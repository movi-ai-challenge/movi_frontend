# MOVI 인증·권한·금융 안전 체크리스트

## 문서 목적

이 문서는 MOVI 프론트엔드의 기능 구현, 코드 리뷰, 백엔드 API 협의에서 빠뜨리면 안 되는 인증·권한·금융 안전 기준을 기록한다.

현재 프론트엔드는 시연용 Mock 데이터와 Mock 인증을 사용한다. Mock 화면이 정상 동작하더라도 실제 인증·인가가 완료된 것으로 간주하지 않는다. 실제 계좌와 거래 API를 연결하기 전 이 문서의 `병합 차단` 항목을 반드시 해결해야 한다.

## 변경할 수 없는 제품 원칙

- 음성 인식 결과만으로 로그인, 송금, 계좌 연결 해제 등 민감한 동작을 완료하지 않는다.
- 금융 거래는 받는 사람, 금액, 출금 계좌를 화면에서 검토하고 사용자가 명시적으로 확인해야 한다.
- 보호자는 위험 거래 알림만 받는다.
- 보호자는 계좌, 잔액, 거래내역을 조회할 수 없다.
- 보호자는 송금을 승인·거절·실행·취소할 수 없다.
- 프론트엔드의 버튼 비활성화나 URL 숨김을 보안 통제로 간주하지 않는다. 인증·소유권·권한은 백엔드가 다시 검증해야 한다.
- 계좌번호, 전화번호, 토큰 등 민감정보를 로그, URL, Git, 오류 메시지에 노출하지 않는다.

## 기능별 필요한 보호 수준

| 기능 | 로그인 세션 | 추가 본인확인 | 백엔드 권한 검증 | 사용자 최종 확인 |
|---|---|---|---|---|
| 계좌·잔액·거래내역 조회 | 필수 | 일반적으로 불필요, 정책 확인 | 사용자 소유 계좌인지 필수 | 불필요 |
| 거래 상세 조회 | 필수 | 일반적으로 불필요, 정책 확인 | 거래가 사용자 계좌에 속하는지 필수 | 불필요 |
| 기본 계좌 변경 | 필수 | 정책 확인 | 사용자 소유 계좌인지 필수 | 변경 버튼 확인 |
| 오픈뱅킹 계좌 연결 | 필수 | 오픈뱅킹 인증 필수 | 연결 결과와 사용자 일치 확인 | 연결·등록 각각 확인 |
| 계좌 연결 해제 | 필수 | PIN·생체인증 등 재인증 필요 | 사용자 소유 계좌와 인증 증명 확인 | 해제 직전 최종 확인 |
| 송금 | 필수 | PIN·생체인증 등 거래 인증 필요 | 계좌 소유권, 한도, FDS, 인증 증명 확인 | 수취인·금액·계좌 검토 후 실행 확인 |
| 보호자 알림 연락처 연결 | 필수 | 사용자 재인증 여부 확인 필요 | 사용자와 초대 요청 소유권 확인 | 알림 수신자 확인 |
| 보호자 초대 수락 | 별도 보호자 본인확인 | 필수 | 서명된 일회용·만료 토큰 검증 | 알림 수신 동의 확인 |
| 위험 거래 알림 발송 | 사용자 화면에서 실행하지 않음 | 해당 없음 | 검증된 FDS 이벤트와 연결 상태 확인 | 해당 없음 |

`정책 확인`으로 표시한 항목은 프론트엔드에서 임의로 결정하지 않는다.

## 현재 발견된 병합 차단 항목

### `main`

- 로그인 화면은 Mock 완료 상태만 표시하며 실제 세션을 만들지 않는다.
- `/accounts`, `/balance`, `/transactions`, `/transactions/[transactionId]`, `/transfer` 하위 경로에 공통 접근 보호가 없다.
- 이체 실행 전에 화면 확인은 있지만 거래 재인증 계약이 없다.
- `5.7 중위험 보호자 승인 대기`는 최신 보호자 정책과 충돌한다. 보호자 승인 흐름을 제거하고 위험 거래 알림 흐름으로 교체해야 한다.
- 거래 상세 조회는 실제 API 연결 시 URL의 거래 ID만 신뢰하면 안 된다. 백엔드가 로그인 사용자 소유 거래인지 확인해야 한다.

### 병합하면 안 되는 기능 브랜치

- `feature/10-3-guardian-risk-alert` / `ebe5b2b`: URL 진입 시 프론트엔드가 알림을 자동 발송한다. 발송은 검증된 FDS 백엔드 이벤트가 수행하고 프론트엔드는 상태만 표시하도록 변경해야 한다.
- `feat/디자인수정` / `e8af421`: 카카오 콜백 URL에서 `accessToken`과 `refreshToken`을 읽는다. 토큰이 브라우저 기록, 로그, 리퍼러에 노출될 수 있으므로 현재 구조를 병합하지 않는다.
- `feature/7-3-guardian-connection-approval` / `a9426bc`: 거래 승인 권한으로 이어지는 설명을 제거하고, 보호자의 본인확인과 위험 거래 알림 수신 동의만 남겨야 한다.
- `feature/7-4-guardian-relationship` / `e7f8652`: 가족 관계 정보가 실제 알림 기능에 필요한지 기획 확인 전까지 병합하지 않는다.

### 진행 중 기능

- `feature/1-5-account-disconnection`: 단순 확인만으로 해제하지 않는다. 계좌 확인, Mock 재인증, 최종 해제를 분리하고 실제 PIN·생체인증 API 계약 전에는 Mock임을 명시한다.
- `feature/global-voice-assistant`: 음성 명령은 화면 이동과 입력 보조까지만 담당한다. 로그인·재인증·거래 최종 확인을 대신할 수 없다.

## 인증 세션 체크리스트

- [ ] 백엔드와 로그인 세션 전달 방식을 확정했다.
- [ ] `HttpOnly`, `Secure`, `SameSite` 쿠키 기반 세션 사용 가능 여부를 확인했다.
- [ ] 액세스 토큰과 리프레시 토큰을 URL 쿼리 또는 해시에 넣지 않는다.
- [ ] 토큰을 콘솔, 오류 추적 도구, 브라우저 기록에 노출하지 않는다.
- [ ] 보호 경로에 직접 접속해도 인증되지 않은 사용자는 로그인 화면으로 이동한다.
- [ ] 로그인 후 원래 접근하려던 안전한 내부 경로로 돌아갈 수 있다.
- [ ] 401 응답은 세션 만료로 처리하고 재로그인을 안내한다.
- [ ] 403 응답은 권한 부족으로 처리하며 로그인 반복으로 해결되는 것처럼 안내하지 않는다.
- [ ] 로그아웃 시 서버 세션과 클라이언트의 금융 상태를 정리한다.
- [ ] 탭 새로고침과 다중 탭 환경의 세션 동작을 확인했다.

## 재인증 체크리스트

- [ ] 재인증 대상 동작을 백엔드와 합의했다.
- [ ] 계좌 연결 해제에는 계좌 ID와 재인증 증명이 함께 검증된다.
- [ ] 송금에는 거래 내용과 결합된 재인증 증명이 사용된다.
- [ ] 재인증 증명의 유효시간과 일회성 여부를 백엔드가 결정하고 검증한다.
- [ ] 다른 계좌나 다른 거래에서 이전 인증 결과를 재사용할 수 없다.
- [ ] 인증 취소·실패·만료 시 금융 동작이 실행되지 않는다.
- [ ] 재인증 완료 후에도 별도의 최종 실행 버튼이 있다.
- [ ] 음성 발화는 재인증 성공으로 취급하지 않는다.

## 송금 및 FDS 체크리스트

- [ ] 수취인, 금액, 출금 계좌를 서버가 다시 검증한다.
- [ ] FDS 위험등급과 위험 사유를 클라이언트가 임의로 지정할 수 없다.
- [ ] 중복 방지 키의 생성·보관·유효 범위를 백엔드와 합의했다.
- [ ] 네트워크 재시도 시 동일 거래가 중복 실행되지 않는다.
- [ ] 성공 화면은 서버에서 확정된 거래 결과만 표시한다.
- [ ] 고위험 거래의 차단 여부와 사용자 후속 행동을 기획·백엔드와 합의했다.
- [ ] 중위험 거래도 보호자 승인을 요청하지 않는다.
- [ ] 보호자에게 보낼 알림 기준 위험등급을 확정했다.

## 보호자 연결 및 알림 체크리스트

- [ ] 보호자 연결의 목적을 `위험 거래 알림 수신`으로만 설명한다.
- [ ] 보호자에게 금융 조회·송금 승인 권한을 제공하는 문구와 UI가 없다.
- [ ] 초대 링크는 추측하기 어려운 서명된 토큰을 사용한다.
- [ ] 초대 링크는 일회용이며 만료시간을 백엔드가 검증한다.
- [ ] 보호자 본인확인이 완료돼야 알림 수신 동의를 저장할 수 있다.
- [ ] 전화번호 오입력·타인 등록을 수정하거나 연결 해제할 방법을 확정했다.
- [ ] SMS 요청 남용을 막기 위한 재전송 제한과 속도 제한을 백엔드와 합의했다.
- [ ] 위험 거래 알림 발송은 브라우저 페이지 진입이 아니라 백엔드 이벤트로 실행된다.
- [ ] 알림 채널, 최소 표시 정보, 재시도 횟수, 실패 처리 방식을 확정했다.
- [ ] 알림 링크가 금융 정보를 보여준다면 별도 인증과 권한 검증을 거친다.

## 백엔드·AI 팀과 반드시 합의할 API 계약

- [ ] 로그인 성공·실패·취소 응답과 세션 전달 방식
- [ ] 세션 만료·갱신·로그아웃 방식
- [ ] PIN·생체인증 등 재인증 시작 및 완료 응답
- [ ] 재인증 증명을 계좌 해제·송금 요청에 전달하는 방식
- [ ] 계좌와 거래의 사용자 소유권 검증 방식
- [ ] 이체 중복 방지 키와 최종 거래 상태 조회 방식
- [ ] FDS 위험등급, 위험 사유, 차단 여부 응답 타입
- [ ] 보호자 초대 토큰의 서명·일회성·만료 정책
- [ ] 보호자 본인확인과 알림 수신 동의 상태
- [ ] 위험 거래 알림 발송 이벤트, 채널, 최소 데이터, 재시도 정책

## 기능 PR 완료 기준

민감 기능 PR은 다음 질문에 모두 답할 수 있어야 한다.

- 누가 이 화면과 API를 사용할 수 있는가?
- 로그인하지 않은 직접 URL 접근은 어떻게 처리되는가?
- 백엔드는 대상 계좌·거래가 사용자 소유인지 어떻게 확인하는가?
- 이 동작에 재인증이 필요한가? 필요 없다면 근거가 정해졌는가?
- 음성만으로 실행될 가능성이 없는가?
- 중복 클릭, 새로고침, 네트워크 재시도에도 한 번만 처리되는가?
- 실패·취소·만료 시 실제 금융 상태가 변경되지 않는가?
- 토큰·계좌번호·전화번호 등 민감정보가 URL과 로그에 남지 않는가?
- Mock 동작과 실제 API 미연동 범위가 화면과 문서에 명시돼 있는가?
- 관련 lint, typecheck, build와 키보드·스크린리더 흐름을 검증했는가?

## 권장 구현 순서

1. 인증 세션 API 계약 확정
2. Mock 세션과 금융 보호 경로 구현
3. 401·403·로그아웃 공통 처리
4. 송금 재인증과 서버 중복 방지 연동
5. 계좌 연결 해제 재인증 연동
6. `main`의 보호자 거래 승인 흐름 제거
7. 보호자 연결을 본인확인·알림 수신 동의 흐름으로 수정
8. 보호자 위험 거래 알림을 백엔드 이벤트 기반으로 수정
9. 인증 우회, 직접 URL 접근, ID 변경, 중복 요청 E2E 테스트

## 결정 기록 규칙

정책이나 API가 확정되면 이 문서의 체크박스를 갱신하고 다음 내용을 함께 기록한다.

- 결정일
- 결정 참여자 또는 담당 팀
- 확정한 동작과 예외
- 관련 API 또는 명세 문서
- 반영한 브랜치와 커밋

확정되지 않은 동작은 `확인 필요`로 유지하며 프론트엔드에서 임의로 구현하지 않는다.
