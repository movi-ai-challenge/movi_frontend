# MOVI Frontend

MOVI는 음성으로 쉽게 쓰는 금융 서비스입니다.

사용자는 계좌를 확인하고, 돈을 보내고, 거래 내역을 볼 수 있습니다. 위험한 송금은 FDS(이상 거래 탐지)가 막거나 보호자에게 알려 줍니다. 음성을 쓰기 어려운 상황을 위해 모든 주요 기능을 키보드와 터치로도 사용할 수 있습니다.

이 저장소에는 Next.js로 만든 프런트엔드만 있습니다. 백엔드와 AI 서버는 각각 다른 저장소에서 관리합니다.

## 지금 상태

> 2026-08-29 기준 · 마감 2026-08-31

주요 화면과 기능은 대부분 만들어졌습니다. 이제 세 서버를 실제로 연결하고, 처음부터 끝까지 테스트하는 일이 가장 중요합니다.

| 파트 | 지금까지 끝난 일 | 남은 일 |
|---|---|---|
| 프런트엔드 | 주요 화면, 실제 백엔드 API 연결, 단위 테스트 62개 | 접근성 실기기 확인, 브라우저 자동 테스트, 작업 브랜치 병합 |
| 백엔드 | 주요 API, 가짜 응답을 사용한 전체 흐름, 테스트 307개 | 오픈뱅킹 돌아오기 수정, AI 연결, 실제 은행 테스트 |
| AI | Voice·FDS 기능, EC2 배포, 백엔드용 음성 API | FDS 데이터 형식 맞추기, 백엔드에서 실제 호출 확인 |

현재 GitHub에 열린 PR은 없습니다. 프런트엔드에는 아래 작업 브랜치가 준비돼 있습니다.

- `feature/accessibility-settings-persistence`: 화면 보기 설정 저장
- `chore/node-test-module-config`: Node 테스트 경고 제거
- `chore/frontend-ci`: GitHub에서 테스트와 빌드를 자동 실행

### 가장 먼저 할 일

| 순서 | 할 일 | 담당 | 상태 |
|:---:|---|---|---|
| 1 | 은행 인증이 끝난 뒤 프런트 화면으로 돌아오게 고치기 | 백엔드 | 작업 중 ([#112](https://github.com/movi-ai-challenge/movi_backend/issues/112)) |
| 2 | 백엔드와 AI를 같은 Docker 네트워크에 연결하기 | 백엔드·인프라 | 브랜치에만 있음 |
| 3 | Voice·FDS 요청과 응답 모양을 맞추고 실제 AI 사용하기 | AI·백엔드 | 확인 중 ([백엔드 #104](https://github.com/movi-ai-challenge/movi_backend/issues/104), [AI #1](https://github.com/movi-ai-challenge/movi_ai/issues/1)) |
| 4 | 테스트 서버에 데모 데이터 켜기 (`movi.seed.enabled=true`) | 인프라 | 서버 설정 필요 |
| 5 | 로그인부터 보호자 알림까지 전체 흐름 시험하기 | 전 팀 | 1~4가 끝난 뒤 가능 |
| 6 | 키보드, 화면 확대, VoiceOver, TalkBack으로 확인하기 | 프런트엔드 | 실기기 확인 필요 |

`staging`은 사용자에게 공개하기 전에 팀이 함께 시험하는 테스트 서버입니다. `E2E`는 로그인부터 송금 결과까지 전체 흐름을 처음부터 끝까지 확인하는 테스트입니다.

AI나 오픈뱅킹 연결이 늦어지면 백엔드의 가짜 응답(Mock)으로 시연합니다. 이 경우 화면과 음성에서 실제 거래가 아닌 시연이라는 점을 분명히 알려야 합니다.

## 꼭 지키는 안전 규칙

- 음성을 쓰지 않아도 키보드와 터치로 같은 일을 할 수 있어야 합니다.
- 음성 인식 결과만으로 로그인하거나 돈을 보내지 않습니다.
- 송금 전에는 받는 사람, 금액, 출금 계좌를 다시 보여 주고 사용자가 직접 확인해야 합니다.
- 프런트엔드는 AI와 FDS를 직접 부르지 않고 백엔드를 거칩니다.
- 로그인 상태, 계좌 주인, 송금 한도와 위험도는 백엔드가 마지막으로 확인합니다.
- 같은 송금 요청이 여러 번 와도 실제 이체는 한 번만 일어나야 합니다.
- 보호자는 위험 거래 알림만 받습니다. 계좌를 보거나 송금을 승인할 수 없습니다.
- 정해지지 않은 API나 결과를 프런트에서 임의로 만들지 않습니다.

## 사용 기술

- Next.js App Router, React, TypeScript
- Tailwind CSS
- Zustand: 화면에서 함께 쓰는 상태 관리
- Axios: 백엔드 API 요청
- npm, Node.js 22.6.0 이상

```text
src/
├── app/                 # 화면과 주소
├── components/common/   # 여러 화면에서 함께 쓰는 UI
├── components/domain/   # 계좌·송금·음성 기능 UI
├── services/            # 백엔드 요청과 응답 확인
├── store/               # 여러 화면이 함께 쓰는 상태
└── types/               # TypeScript 데이터 모양
```

## 내 컴퓨터에서 실행하기

먼저 필요한 패키지를 설치하고 환경 설정 파일을 만듭니다.

```bash
npm ci
cp .env.example .env.local
```

백엔드 없이 화면만 확인하려면 `.env.local`을 다음처럼 설정합니다.

```env
NEXT_PUBLIC_API_URL=http://localhost:8080
NEXT_PUBLIC_USE_MOCK=true
```

실제 로컬 백엔드와 연결하려면 `NEXT_PUBLIC_USE_MOCK=false`로 바꿉니다. 설정을 바꾼 뒤에는 개발 서버를 다시 시작해야 합니다.

```bash
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

`.env.local`, 토큰, 실제 계좌번호, 전화번호와 개인정보는 Git에 올리지 않습니다.

## 코드 확인하기

변경한 코드를 올리기 전에 아래 명령을 모두 실행합니다.

```bash
npm test          # 단위 테스트
npm run typecheck # TypeScript 오류 확인
npm run lint      # 코드 규칙 확인
npm run build     # 배포용 빌드 확인
```

이 명령이 모두 성공해도 실제 서비스 확인이 끝난 것은 아닙니다. 테스트 서버, 실제 브라우저, 휴대전화와 화면 읽기 프로그램에서도 확인해야 합니다.

## 데모 데이터

백엔드가 `movi.seed.enabled=true`로 실행되면 아래 데모 데이터를 만듭니다.

| 항목 | 값 |
|---|---|
| 데모 사용자 | `01012345678` / PIN `135790` |
| 다른 사용자 | `01099998888` / 같은 PIN |
| 계좌 | 생활비 통장 53만 원(기본), 비상금 통장 120만 원 |
| 받는 사람 | 엄마·아들(보낸 적 있음), 김영희(처음 보냄) |

위험도는 다음과 같이 확인합니다.

| 위험도 | 시험 방법 | 결과 |
|---|---|---|
| LOW | 엄마에게 10만 원 이하 보내기 | 송금 완료, 알림 없음 |
| MEDIUM | 김영희에게 보내거나 10만 원 넘게 보내기 | 송금 완료, 보호자 알림 |
| HIGH | 비상금 통장에서 70만 원 이상 보내기 | 송금 차단, 보호자 알림 |

HIGH 시험은 비상금 통장을 사용해야 합니다. 생활비 통장은 잔액이 53만 원이라 위험도를 확인하기 전에 잔액 부족으로 멈춥니다.

LOW 결과를 보려면 먼저 PIN 로그인을 한 번 해야 합니다. 백엔드는 PIN 로그인을 마친 기기를 익숙한 기기로 봅니다. 처음 보는 기기는 소액을 보내도 MEDIUM이 될 수 있습니다.

## 작업 방법

1. 최신 `main`에서 새 브랜치를 만듭니다.
2. 한 브랜치에서는 한 가지 일만 합니다.
3. 기능은 `feature/<이름>`, 문서와 설정은 `chore/<이름>`을 사용합니다.
4. 테스트, 타입 검사, lint와 build를 모두 실행합니다.
5. 브랜치를 원격에 올리고 리뷰를 받은 뒤 `main`에 합칩니다.
